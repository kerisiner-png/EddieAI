## Конституция изменений

1. НИКОГДА не изменяй код, данные или конфигурацию без явного запроса
   пользователя.
2. Найденная проблема ≠ разрешение на исправление. Схема:
   проблема → последствия → варианты решения → подтверждение.
3. Не переписывай существующие подсистемы; минимальные диффы;
   обратная совместимость.
4. НЕ трогай DecisionRuntime / LLM-интеграцию без отдельного решения.
5. Любое изменение данных личности (`data/*.db`, `self_state.json`,
   `user_state.json`) — только после бэкапа и только через легитимные
   конвейеры проекта (evidence → proposal → lifecycle).
6. Коммиты в этом репозитории — только по явному запросу пользователя.

## Критические правила кодировок

[Урок 21–22.08.2026: болезнь кодировок повредила десятки файлов в обоих
проектах и данные личности.]

- Все файлы строго UTF-8 БЕЗ BOM.
- Запрещено править исходники через PowerShell `Set-Content`/
  `Out-File`/`Add-Content` (они пишут cp1251/BOM).
- После любых правок: байтовая проверка отсутствия литеральных «?»
  там, где ожидается русский текст, и признаков двойного
  перекодирования («Ð» и т.п.).
- При поиске кириллицы в логах через pipe/heredoc использовать
  `\uXXXX`-паттерны или grep по байтам UTF-8.

## MCP-серверы (глобальный конфиг opencode)

Подключены через `~/.config/opencode/opencode.jsonc` (блок `mcp`),
доступны во всех сессиях. Правила:

- **TestSprite** — облачное ИИ-тестирование: веб-UI по URL и API по
  base URL. Нативный Win32 дашборд им НЕ тестируется.
  - Запускать ТОЛЬКО по явной просьбе Эдди: каждый прогон расходует
    кредиты тарифа.
  - Ключ хранится только в глобальном конфиге; НЕ копировать его в
    файлы проекта, логи, отчёты, коммиты и чат.
  - API-тесты направлять на тестовые/локальные эндпоинты
    (например `http://127.0.0.1:8090/v1`); запрещено давать тестам
    писать в продакшн-данные личности (`data/*.db`, self/user_state).
  - Результат прогона — отчёт со списком проблем; изменения кода по
    находкам — только после подтверждения совета (Конституция, п.2).
- **Context7** — свежая документация библиотек (remote). Использовать
  для сверки API библиотек перед написанием/правкой кода; локальных
  ресурсов не потребляет.
