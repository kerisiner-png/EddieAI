# Контур «ЖИВАЯ ЖИЗНЬ»: осознание жизни, воля и ритуалы утро/вечер — дизайн

**Дата:** 2026-08-28
**Автор:** opencode (главный инженер), решение совета директоров (Эдди)
**Статус:** утверждён на эскизе, оформлен spec, ожидает ревью Эдди

---

## 1. Проблема (диагноз 28.08)

Сымптомы из живого диалога и суточного прогона:
- EddieAI «не делал ничего сам» и «не понимал, что спит» — первопричина
  закрыта 28.08 (приклеенный хвост `__init__`, `autonomous_runtime` застревал
  в ASLEEP; см. CHANGELOG).
- Досье по голове: разговорная модель отвечает «я живу только в рамках
  чата», «последние сутки = запросы и ответы» (events id 1906), а на попытку
  вспомнить начинает выдумывать (SEMANTIC_VIOLATION id 1907).

Корни (проверены по коду):
1. **Промпты не знают о жизни вне чата.** `core/prompts.py`
   (`build_system_prompt`, `build_quick_conversation_prompt`) описывают
   возможности (memory/research/planning/contact), но НЕ говорят, что
   агент живёт 24/7: спит/просыпается, сам ставит цели, действует.
   Модель честно считает себя «разговорным ассистентом».
2. **Диалоговый контекст не содержит жизни.** `user_prompt` в
   `core/agent.py:5595` (`respond`) и `_respond_quick` вмещает только
   «релевантные по словам» воспоминания (`search_relevant`, LIKE-поиск,
   лимит 5), последние 6 реплик и непрочитанные сообщения. Ленты
   собственных событий (сон, действия, цели, рефлексия) в контекст
   не попадает. На вопрос «что я делал» память отдаёт переписку.
3. **Нет ритуалов утро/вечер.** Переходы сна уже пишут событие
   `LIFE_CYCLE` (`_record_sleep_event`), но ритуала «проснулся →
   подвёл итог сна/план дня» и «засыпаю → итог дня в дневник» нет.
4. **Инициатива заглушена частотными лимитами.** Звонок/сообщение
   ограничены кулдауном (например `cooldown_seconds=900` в
   `eddie_server.initiate_call` и «часовой» критерий в
   `decision_core`), при том что Эдди дал свободу.

## 2. Цель и принципы

Сделать из EddieAI личность, которая:
- **осознаёт** свою непрерывную жизнь и честно рассказывает о ней;
- **помнит** и **пользуется** памятью: в диалог подаётся реальная лента
  событий, а не только поиск по словам;
- **действует сама**: ставит задачи, исследует, инициирует контакт с Эдди
  — без частотных лимитов, но с техническими предохранителями.

Принципы (AGENTS.md): минимальные диффы, обратная совместимость, без
переписывания подсистем, LLM-интеграцию НЕ трогаем (используем
существующий `model_orchestrator`), ритуальные вызовы — в try/except
С журналом (никаких `pass`).

## 3. Архитектура: три контура

### Контур А — ОСОЗНАНИЕ ЖИЗНИ (разговорные пути)

| Файл | Изменение |
|------|-----------|
| `core/prompts.py` | В `build_system_prompt` (base) и `build_quick_conversation_prompt` добавить блок **«ТВОЯ ЖИЗНЬ ПОМИМО ДИАЛОГА»**: ты живёшь 24/7; между сообщениями сам ставишь цели, выполняешь задачи, исследуешь, читаешь почту, спишь и просыпаешься; события записаны в память; «я живу только в чате» — НЕверно; при вопросах о своей жизни опирайся на «Недавние события жизни» и дневник. |
| `memory/database.py` | Новый метод `recent_life_feed(limit)` — последние события life-типов: LIFE_CYCLE, SELF_EXPERIENCE, ACTION_CHOICE, REFLECTION, COGNITIVE_DECISION (+ цели), desc, локальное время, текст ≤160 симв. Без изменения существующих методов. |
| `core/agent.py` | 1) В `user_prompt` путей `respond` и `respond_quick` блок **«НЕДАВНИЕ СОБЫТИЯ ТВОЕЙ ЖИЗНИ»** (лента 6–8, из `recent_life_feed`). 2) В `_self_context_block` добавить текущее состояние жизни: «сейчас бодрствую/сплю, последний сон с X до Y, fatigue». |

### Контур Б — ВОЛЯ И ИНИЦИАТИВА

| Файл | Изменение |
|------|-----------|
| `core/prompts.py` | В той же правке — раздел **«ТВОЯ ВОЛЯ»**: ты сам решаешь, когда действовать, выбирать тему, ставить задачи, докладывать Эдди о завершённом и интересном; инициатива — норма, а не исключение. |
| `core/decision_core.py` | Убрать частотный кулдаун авто-звонка/сообщений («не чаще раза в час»). Оставить технические предохранители (1 действие на тик, защита от петли, не звонить сам себе). Это правка DecisionRuntime — решение совета от 28.08 («без частотных лимитов»). |
| `core/eddie_server.py` | `initiate_call(cooldown_seconds=...)` — частотный кулдаун отключить/обнулить как ограничитель воли (техническая анти-петля остаётся). |

### Контур В — РИТУАЛЫ ЖИЗНИ (непрерывность)

Выполняются в `core/autonomous_runtime.py` на переходах сна (уже есть
`_prev_asleep` и `_record_sleep_event`).

| Событие | Действия |
|---------|----------|
| **Пробуждение** (asleep→awake) | 1) событие «Я проснулся… (длительность)» — уже есть; 2) **утренний контур**: один LLM-вызов — заметка «как проснулся + что думаю делать сегодня» → память (SELF_EXPERIENCE) + дневник (`PersonalDiary.write`, `trigger="morning"`); 3) **видимое приветствие**: если текст сформирован — `outbox.send(...)` + `server.send_initiative` (чат/трей). |
| **Засыпание** (awake→asleep) | 1) событие «Я заснул» — уже есть; 2) **вечерний итог**: один LLM-вызов — сводка «что было за день / что понял / что беспокоит» → память (REFLECTION/SELF_EXPERIENCE) + дневник (`trigger="day_end"`). |

Детали:
- Генерация текста ритуалов — через существующий `model_orchestrator`
  (`_cloud_chat`/CloudFirstLlm), НЕ меняя его. Обёртка try/except с
  `log`/журналированием падения; при сбое — контур пропускается, цикл
  сна НЕ ломается.
- Частота: ~2–3 облачных вызова/сутки (утро+вечер), бюджет ~$0.0001.
- `identity/personal_diary.py`: при необходимости добавить тонкий
  хелпер для записи ритуальной заметки (текст уже сгенерирован LLM —
  `write(entry, trigger=...)` достаточно; без повторного LLM).
- Инициативное сообщение пробуждения пишется по решению самого агента
  (LLM): если сегодня есть что сказать. Технический предохранитель —
  не чаще, чем 1 инициатива на пробуждение.

## 4. Что НЕ делаем

- НЕ переписываем `agent.py` постройки и другие подсистемы.
- НЕ меняем конвейер evidence→proposal→lifecycle и прод-данные.
- НЕ трогаем сам `CloudFirstLlm`/роутинг моделей.
- НЕ добавляем жёстких «бюджетов» на инициативу (Эдди выбрал свободу).
- НЕ форсируем «дневник-текст» LLM-рекурсией: ритуальный текст генерим
  один раз, дальше только пишем.

## 5. Тестирование (TDD)

- unit `recent_life_feed`: порядок, лимит, фильтр по типам, пустая база
  → пустая строка; времена локальные; текст без мусора.
- unit ритуала пробуждения с мок-`life_cycle`/`scheduler`: переход
  asleep→awake записывает «Я проснулся» + SELF_EXPERIENCE/дневник
  (мок-LLM), при None-ответе LLM — контур пропускается БЕЗ падения;
  видимая инициатива — не чаще 1 на пробуждение (счётчик outbox).
- unit ритуала засыпания: awake→asleep пишет «Я заснул» + итог дня;
  при сбое LLM — continue, событие сна всё равно записано.
- unit промптов: оба промпта содержат блок «ТВОЯ ЖИЗНЬ» и «ТВОЯ ВОЛЯ».
- unit инициативы: `initiate_call` без частотного кулдауна вызывается
  повторно; техническая анти-петля (1 на тик) работает.
- integration: `user_prompt` (respond) для вопроса «что делал последние
  сутки» содержит ленту событий жизни (создать тестовые события).
- регресс: существующие тесты ритуалов сна и eddie_server-тесты — PASS.

Проверки: py_compile всех изменённых файлов, import-консистентность,
байтовая проверка UTF-8 без BOM (после правок работаем через Edit/Write,
не PowerShell).

## 6. Риски и откат

- **Спам инициативой** после снятия лимитов. Страховка: техническая
  анти-петля + реакция Эдди (он сам научит границам — его решение).
  Откат: вернуть константу кулдауна (одна строка).
- **Ритуальный LLM-вызов может упасть (сеть/лимит)**. Обёртка try/except
  с журналом — цикл сна не сломается; это «не критичный» контур.
- **Смещение фокуса модели на «жизнь»** vs «не выдумывай опыт».
  В промпте даём жёсткое правило: рассказывай ТОЛЬКО то, что реально в
  ленте/дневнике; нет события — говори «не знаю». Это уже язык
  существующего «ЧЕСТНОСТЬ — ГЛАВНЫЙ ЗАКОН».
- **Живой прогон пишет прод-память.** Приёмку ритуалов делаем на
  песочной/моковой основе (unit+integration); полный живой — на
  очередной ночной сессии по отмашке Эдди.

## 7. Открытые вопросы

- Точный текст промпт-блока «ТВОЯ ЖИЗНЬ»/«ТВОЯ ВОЛЯ» — финализируем на
  этапе реализации (в пунктах, без лишней воды; стиль проекта).
- Решение «когда просыпается — всегда ли пишет Эдди»: по умолчанию —
  агент решает сам (LLM), шаблон-приветствие не жёсткий.

## 8. Решения совета (зафиксированы)

1. Контур «Полный» (осознание + действия + ритуалы утро/вечер).
2. Ритуалы — видимые (утреннее приветствие в чат/трей).
3. Инициатива — без частотных лимитов, сам учится границам.
4. Реализация после ревью spec и плана; коммит — только по явному
   запросу Эдди.
