# Этажи 9 и 8 подъёма: инструменты как живой орган + мир-модель — дизайн

**Дата:** 2026-08-30
**Автор:** opencode (главный инженер), решение Эдди 30.08
**Статус:** дизайн утверждён в чате, оформлен spec, ожидает ревью Эдди

---

## 1. Проблема (диагноз 30.08)

Подъём по этажам ROADMAP упирается в два блокера:

- **Этаж 9 «Инструменты» — каркас есть, жизни нет.** `ToolRegistry`,
  `ToolExecutionPolicy`, `FilesystemExecutor`, `WebExecutor`, `ToolRunner`
  (validation → routing → policy → execution) и `ActionPlanner`
  (READ_FILE/WEB_SEARCH/RESEARCH/THINK) полностью рабочие, и
  `AgentLoop.run_once()` исполняется в автономном тике
  (`autonomous_cycle`, `autonomy_orchestrator`). Но **источника задач
  нет**: `goal_generator` не создаёт исследовательских целей, а
  `InitiativeEngine` срабатывает только когда уже есть активная цель.
  В результате в автономии инструменты молчат: личность не читает свой
  код, не смотрит в веб, не исследует — «каркас зарегистрирован, но
  реальное использование отсутствует».
- **Этаж 8 «Мир» — почти пустой.** Есть `time_perception` (время/день)
  и `resource_watchdog` (RAM через чистый `ctypes` Win32 API, без
  psutil). Нет показателей ПК (CPU, диск, процессы, сеть), нет
  отношения личности к месту обитания (структура C:\EddieAI, роль в
  проекте), нет снимков мира в память. Личность не знает, где живёт и
  что происходит с её хостом.

Цель (по решению Эдди):
- Инструменты становятся **живым органом**: личность сама выбирает тему
  для исследования (гибрид: детерминированный выбор из интересов +
  раз в сутки LLM-тема из снов/рефлексии) и исполняет её через
  существующий контур. **Жёстких квот нет** — вместо них осведомлённость
  личности о собственных тратах (web-поиски за сутки, облачные вызовы,
  RAM), на основе которой она сама себя благоразумно ограничивает.
- Мир-модель: **снимок состояния ПК по событию/запросу** (низкая RAM,
  сбой контура, инициатива «проверить мир», вопрос Эдди) + **сводка
  места обитания** (структура C:\EddieAI, назначение папок, роль
  личности в проекте).

## 2. Цель и принципы

Личность, которая:
- **сама исследует**: раз в время выбирает тему по интересам/наблюдениям
  и полноценно использует READ_FILE/WEB_SEARCH/RESEARCH;
- **осознаёт цену своих действий**: видит метрики использования и сама
  решает «могу себе позволить ещё» / «дадим мозгу усвоить»;
- **знает, где живёт**: понимает структуру своего каталога и состояние
  своего хоста, когда это важно.

Принципы (AGENTS.md): минимальные диффы, обратная совместимость,
`DecisionRuntime` и роутинг моделей не трогаем; LLM — только существующий
`CloudFirstLlm` (раз в сутки, как «редкий генератор»); без новых
зависимостей (stdlib: `ctypes` + подпроцессы WMI); запись — только через
легитимные конвейеры (events/knowledge/life); все новые вызовы — в
try/except с журналом (никаких голых `pass`).

## 3. Архитектура

### Контур 9.1 — `CuriosityDirector` (новый модуль `core/curiosity.py`)

Детерминированный выбор темы → исследовательская цель в `goal_manager`
→ существующий `AgentLoop.run_once()` → `ActionPlanner` → `ToolRunner`.
Ничего в agent_loop/decision_core не переписывается.

| Элемент | Назначение |
|---------|-----------|
| `CuriosityDirector` | Решает «исследовать сейчас или нет» и какую тему. Смотрит: интересы (`self_state`/interests), последние наблюдения (events), осведомлённость о тратах, фазу суток (сон/бодрствование). Частота — «редко» (намерение, не жёсткая квота): не чаще раз в `min_interval_seconds` (конфигурируемо, по умолчанию ~30 мин) и не во время сна. |
| `select_topic()` | Возвращает тему в формате цели: «Исследовать тему: <запрос>», «Прочитать файл: <путь из sandbox>», «Разобраться в наблюдении: <что>». Источники тем детерминированы: ротация интересов, недавние события без исследовательской цели, вопросы «чего я не знаю о своём коде». Без LLM. |
| `daily_llm_topic()` | Раз в сутки: через существующий `CloudFirstLlm.chat()` с контекстом последних снов + рефлексии просит одну тему для исследования. 1 облачный вызов/сутки. Результат сохраняется как запасная тема. |
| Осведомлённость | Счётчики в `self_state` (ключи `usage_today`): `web_searches`, `llm_calls`, `available_ram_mb`. Хуки: `ToolRunner` инкрементирует `web_searches` при реальном WEB_SEARCH; `CloudFirstLlm.chat` инкрементирует `llm_calls`; `ResourceWatchdog.check()` кладёт `available_ram_mb`. `CuriosityDirector` учитывает их: при высоких значениях или низкой RAM может вернуть «подождать» с объяснением. |

Формат цели (обратная совместимость): создаётся через `goal_manager`
обычным конвейером (как создаются другие цели), титул проходит через
существующие `ActionPlanner` keyword-правила.

### Контур 8.1 — `WorldProbe` (новый модуль `core/world_probe.py`)

Снимок состояния ПК по событию/запросу. Чистый stdlib.

| Элемент | Назначение |
|---------|-----------|
| `probe()` | Собирает: RAM (переиспользовать `_available_memory_mb` из `resource_watchdog` или ctypes `GlobalMemoryStatusEx`), CPU (осторожно, через `NtQuerySystemInformation`/`GetSystemTimes`), диск C: (`GetDiskFreeSpaceEx`), топ-процессы по памяти (WMI `Win32_Process` через подпроцесс или `CreateToolhelp32Snapshot`), сетевое состояние (WMI `Win32_NetworkAdapter`/скромно). Все метрики в try/except с журналом; частичный снимок допустим. |
| `probe_pc()` интерфейс | `trigger()` метода ограничивает: не чаще раз в N минут (анти-спам) + конфигурируемая блокировка во время сна. |
| Инициация | По триггерам: `resource_watchdog` наблюдал low/critical RAM, сбой голосового контура, инициатива личности «проверить мир» (как тема в `CuriosityDirector`), запрос Эдди. |
| Результат | Короткая сводка «мир сейчас» (текст ≤ ~300 симв) — в контекст промпта + событие `WORLD_SNAPSHOT` в память (через существующий `events`-конвейер). Хранение снимков — таблица events, без новой БД. |

### Контур 8.2 — Сводка места обитания

| Элемент | Назначение |
|---------|-----------|
| `build_world_description()` | Один раз (и по ревизиям) собирает из PROJECT_STATE.md/docs/структуры C:\EddieAI: что за каталог, назначение подпапок (core/identity/memory/data/docs_engineer), ключевые файлы (ROADMAP, PROJECT_STATE), роль личности. Хранится в `self_state.world_description`. |
| Включение в контекст | Сводка подаётся в промпт (блок «ГДЕ ТЫ ЖИВЁШЬ»), короткая (≤ ~400 симв), без постоянного сканирования. |

## 4. Поток данных

1. Тик автономного цикла → `CuriosityDirector.evaluate()`.
2. Если «исследовать»: создаёт цель через `goal_manager` (или отдаёт
   существующему циклу) → `AgentLoop.run_once()` находит цель и
   исполняет задачь через `ActionPlanner.plan()` → `ToolRunner.run()`.
3. Результат инструмента фиксируется как обычно (action в events,
   appraisal, external research → внешние знания). Счётчики
   осведомлённости обновляются.
4. При запросе/событии → `WorldProbe.probe()` → сводка в контекст +
   событие `WORLD_SNAPSHOT`.

## 5. Безопасность

- ФС: только чтение в sandbox `C:\EddieAI` (write остаётся disabled,
  `allow_powershell=False`).
- Web: только `WEB_SEARCH` + `read_page` через существующую политику;
  `_is_safe_url` не допускает private/loopback сети.
- LLM: один существующий `CloudFirstLlm` вызов/сутки; новые пути LLM не
  добавляются.
- Данные личности: напрямую не меняются; новые ключи `self_state`
  (`usage_today`, `world_description`) — аддитивные.
- Снимки ПК не покидают машину; в память пишется только сводка (не
   сырые данные процессов).

## 6. Тестирование (TDD)

Unit:
- `CuriosityDirector`: выбирает тему из интересов; соблюдает «редкость»
  (не срабатывает в кулдауне и во сне); реагирует на осведомлённость
  (при высоких тратах/низкой RAM возвращает «подождать»);
  `select_topic` не вызывает LLM.
- `daily_llm_topic`: вызывает `CloudFirstLlm` с контекстом снов,
  результат — валидная тема; при падении LLM — graceful (нет темы, не
  падает).
- `WorldProbe`: возвращает валидный снимок при mock ctypes/WMI;
  частичная поломка метрик не роняет сбор; throttle работает.
- `build_world_description`: собирает сводку без ошибок, текст ≤ лимита.

Интеграция:
- Тестовый тик: `CuriosityDirector` → созданная цель → `AgentLoop.run_once()`
  со stub-`tool_runner` → реально появляются READ_FILE/WEB_SEARCH действия.

Регресс: `test_production_runtime`, `test_decision_revive`, существующие
сюиты не падают.

## 7. Критерии приёмки

1. `CuriosityDirector` в проде за сутки реально создаёт ≥ 1
   исследовательской цели и она исполняется инструментами
   (в логе night-прогона появляется действие READ_FILE/WEB_SEARCH,
   не отклонённое политикой).
2. Ноль новых SEMANTIC_VIOLATION/INTERNAL_LEAK из-за мира/любопытства.
3. `WorldProbe` по триггеру даёт валидную сводку и пишет
   `WORLD_SNAPSHOT` без падений.
4. Сводка места обитания появляется в context промптов.
5. Расход облака: ≤ 1 новый LLM-вызов/сутки (тема), все остальные
   пути детерминированы.
6. Регресс-тесты зелёные; суточный прогон жив; RAM не страдает
   (снимки только по триггеру).
