# EddieAI Messenger — спецификация дизайна

**Дата:** 2026-08-26
**Автор:** opencode (главный инженер)
**Статус:** на утверждении Эдди

---

## 1. Обзор

Превратить текущий чат (`communication/`) в полноценный мессенджер
между Эдди и EddieAI: персистентная история переписки, ресипты
«прочитано», индикатор «думает», статус присутствия. Оба собеседника
видят, когда другой прочитал сообщение и думает ли он.

## 2. Архитектура

```
┌──────────────────────────────────────────────┐
│            EddieAI Messenger (tkinter)        │
│  ┌─────────┐  ┌────────────────────────────┐ │
│  │  Tray   │  │  Chat Window               │ │
│  │ (pystray│  │  История из chat_history   │ │
│  │  icon)  │  │  + галочки ✓/✓✓ + статус   │ │
│  └────┬────┘  └───────────┬────────────────┘ │
│       │                   │                  │
│  ┌────┴───────────────────┴────────────────┐ │
│  │ TCP Client (port 7778)                  │ │
│  │  user_message / mark_read /              │ │
│  │  history / agent_thinking / agent_msg    │ │
│  └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
              │ TCP
┌─────────────┴──────────────────────────────┐
│           EddieServer (port 7778)           │
│  ┌────────────────────────────────────────┐ │
│  │ chat_history таблица (memory.db)       │ │
│  │ запись сообщений, ресипты, история     │ │
│  └────────────────────────────────────────┘ │
│  Agent.respond() — мозг (CONVERSATION в память)│
└──────────────────────────────────────────────┘
```

Два слоя данных:
- `chat_history` — сырой лог мессенджера (для UI, ресиптов, истории)
- `memory.db events (CONVERSATION)` — внутренний опыт EddieAI
  (аффект, интерпретация) — НЕ трогаем, продолжает писаться

## 3. Хранилище: таблица chat_history

В `memory.db`:

```sql
CREATE TABLE IF NOT EXISTS chat_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sender TEXT NOT NULL,          -- 'Eddie' | 'EddieAI'
    text TEXT NOT NULL,
    ts TEXT NOT NULL,              -- ISO timestamp UTC
    read_by_recipient INTEGER DEFAULT 0,
    read_ts TEXT
);
```

- `read_by_recipient`: для сообщения Eddie=1 когда EddieAI получил
  и начал думать; для EddieAI=1 когда Эдди прочитал (окно открыто).
- Методы: `add_message(sender, text) -> id`, `mark_read(msg_id)`,
  `recent(limit) -> list`, `unread_count() -> int`.

## 4. Протокол (TCP JSON) — дополнение к существующему

| Тип | Направление | Поля | Назначение |
|-----|-------------|------|------------|
| `user_message` | клиент→сервер | text | существующий |
| `agent_message` | сервер→клиент | **msg_id**, text | ответ + id |
| `agent_initiative` | сервер→клиент | **msg_id**, text | инициатива + id |
| `agent_thinking` | сервер→клиент | msg_id | EddieAI получил, думает |
| `mark_read` | клиент→сервер | msg_id | Эдди прочитал сообщение |
| `history` | сервер→клиент | messages:[{id,sender,text,ts,read}] | пачка при коннекте |

## 5. EddieAI — пользователь мессенджера (автономия чтения)

EddieAI НЕ отвечает мгновенно и НЕ пишет всё в память. Для него
чат — тоже мессенджер, как для Эдди.

**Поток Ты → EddieAI:**
1. Сообщение ложится в chat_history (sender=Eddie, read_by_recipient=0)
   → клиент показывает ✓ (доставлено), БЕЗ ответа
2. Сервер НЕ вызывает respond(), НЕ пишет в CONVERSATION
3. Каждый тик decide() EddieAI видит: unread (твои непрочитанные) +
   время отправки. Он САМ решает прочитать сейчас или отложить
   (эвристика: любопытство / занятость целью / сколько уже висит)
4. Решил → сервер mark_read непрочитанных Eddie → respond()
   (ТОГДА пишет CONVERSATION в память) → ответ клиенту асинхронно
5. Не решил → остаётся непрочитанным, он занят своим

**Поток EddieAI → Ты + повтор:**
- Пишет через send_initiative → chat_history (непрочитано для тебя)
- Видит твой read_by_recipient + время → САМ решает написать снова
  и как скоро/часто (без жёстких таймеров, по своей природе)

**Чувство времени:** каждое сообщение имеет ts; EddieAI в решении
учитывает «сколько уже висит непрочитанное».

**Память = граница:** chat_history = «телефон». CONVERSATION пишется
только когда EddieAI реально прочитал и вступил в диалог.

## 6. Ресипты «прочитано»

**Сообщение Эдди (EddieAI-получатель):**
1. Сервер получает `user_message` → `chat_history.add_message('Eddie', ...)`
   → шлёт клиенту `ack` (✓ доставлено). respond() НЕ вызывается.
2. Когда EddieAI решает прочитать (раздел 5): сервер mark_read
   непрочитанных Eddie → respond() → шлёт `agent_message`
3. Клиент: твоё сообщение показывает `✓` → `✓✓ прочитано` (когда
   EddieAI зашёл читать)

**Сообщение EddieAI (Эдди-получатель):**
1. Сервер шлёт `agent_message`/`agent_initiative` → пишет в `chat_history`
2. Клиент, когда окно открыто и сообщение показано → шлёт `mark_read`
3. Сервер ставит `read_by_recipient=1` + `read_ts`; EddieAI в decide()
   видит, прочитал ли Эдди его сообщения, и решает написать снова

## 6. UI

- При открытии окна: `history` → показать последние ~50 сообщений
- Галочки: `✓` (доставлено, нет mark_read) → `✓✓` (прочитано)
  у сообщений Эдди
- Статус-бар: «EddieAI онлайн» / «EddieAI думает...» / «Оффлайн»
- Текущее поведение крестика (свернуть в трей) сохранить
- Группировка по времени, автопрокрутка — сохранить

## 8. Запуск и рестарт

- Сборка на отдельном тестовом сервере/БД — не мешает текущей ночи
- После готовности: решить с Эдди — перезапустить ночь сейчас (потеря
  ~1-2ч автономии) или развернуть утром
- Команда запуска не меняется: `python night_run.py --minutes N`
