# Локальное ядро решений — Implementation Plan

**Goal:** Перевести автономию EddieAI с «LLM на каждое решение» на
«локальное ядро решений (бесплатно, 24/7) + LLM только для формирования
новых паттернов и генерации».

**Architecture:** Два слоя. Слой А — локальный конечный автомат/правила
(присутствие, почта, выбор цели/задачи, маршрутизация, аффект, «что
дальше»). Слой Б — LLM-гейт (новая ситуация → паттерн; план цели;
выводы дня; ответ Эдди; редкая рефлексия). Хранилище паттернов = уже
существующие evidence/habit/preference/behavior + новый ключ «ситуация→действие».

**Tech Stack:** Python, без новых зависимостей.

**Spec:** `docs_engineer\SPECS\2026-08-26-local-decision-core-design.md`

## Global Constraints

- UTF-8 no BOM, no comments, project style (vertical, blank-line groups)
- НЕ добавлять «бюджет-предохранитель» и НЕ крутить интервалы вручную
- Локальное ядро должно выполнять рутину с НУЛЯ LLM-вызовов
- LLM вызывается ТОЛЬКО: новый паттерн, план цели, выводы дня, ответ
  Эдди, редкая рефлексия
- Мессенджер и общение с Эдди не трогать (уже дёшево/бесплатно)
- Свежая сессия: дизайн в SPECS, читать перед работой

### Задача 1: Кодировщик ситуации (situation encoder)
- Новый модуль `core/situation.py`: функция `encode_situation(state) -> str`
  (стабильный строковый ключ текущей ситуации: активная цель, тип задачи,
  наличие непрочитанного, аффект, время суток/свежесть).
- Цель: два одинаковых состояния дают одинаковый ключ → поиск паттерна.
- Тест: два вызова с одинаковым state → одинаковый ключ; с разным → разные.

### Задача 2: Хранилище «ситуация → действие»
- В `memory/database.py`: таблица `situation_patterns`
  (situation_key UNIQUE, action TEXT, confidence REAL, times_used INT,
  first_seen, last_seen).
- Методы: `pattern_lookup(key)`, `pattern_record(key, action, confidence)`,
  `pattern_bump(key)` (times_used++).
- Тест: запись → lookup → bump → times_used=2.

### Задача 3: Локальное ядро решений
- Новый модуль `core/decision_core.py`: класс `DecisionCore`.
- Метод `decide(state) -> Action`: 
  1. encode_situation(state)
  2. pattern_lookup → есть → вернуть действие (БЕЗ LLM)
  3. нет → вернуть `NEEDS_NEW_PATTERN` (сигнал LLM-гейту)
- Включает локальные правила для рутины: выбор цели/задачи (из
  goal_manager/task_controller), проверка почты (inbox), аффект.
- Тест: рутинное действие возвращается без вызова LLM (мок model = None).

### Задача 4: LLM-гейт (редкий генератор паттернов)
- В `decision_core.py`: метод `learn(situation_key, context) -> Action`:
  вызывает LLM ОДИН раз → формирует действие → `pattern_record` →
  возвращает действие.
- Вызывается ТОЛЬКО когда `decide()` вернул `NEEDS_NEW_PATTERN`.
- Ограничение частоты обучения естественное (новых ситуаций всё меньше).
- Тест: новизна → 1 LLM-вызов → паттерн сохранён → следующий раз без LLM.

### Задача 5: Интеграция в orchestrator
- `core/autonomy_orchestrator.py`: `_decide()` и `tick()` переходят на
  DecisionCore: сначала почта (локально), затем local decide, LLM-гейт
  только на новизну. Убрать частые прямые вызовы goal_plan_generator/
  рефлексии из рутины.
- Убрать 5-мин интервал: локальное ядро крутится постоянно (runtime
  цикл), LLM-гейт сам редок.
- Тест: сессия с рутиной выполняет N шагов с 0-1 LLM-вызовов.

### Задача 6: Обучение из памяти (паттерны накапливаются)
- На консолидации/рефлексии: из накопленных evidence/habits формировать
  паттерны ситуаций, чтобы LLM вызывался всё реже.
- Тест: после обучения число NEEDS_NEW_PATTERN падает.

### Задача 7: Живая проверка
- Запуск night_run короткий (5-10 мин): замерить число LLM-вызовов —
  рутина должна идти локально, вызовы только на новизну/ответы.
- Сравнить с прежним (десятки вызовов) → должно быть кратно меньше.

## Критерий приёмки
- Рутинная автономия (почта, выбор цели/задачи, аффект, маршрутизация)
  выполняется с НУЛЯ LLM-вызовов.
- LLM вызывается только: новая ситуация (обучение паттерна), план цели,
  выводы дня, ответ Эдди, редкая рефлексия.
- Паттерны накапливаются и переиспользуются между сессиями (таблица
  situation_patterns растёт, вызовы падают).
- 5-мин интервал убран, ядро крутится постоянно и бесплатно.
