## АКТУАЛЬНОЕ

### Правки кода
- **Якорь правки**: точечная правка «по хвосту метода» без заголовка
  следующего def приклеивает код внутрь ЧУЖОЙ функции (случай:
  _draw_water влезла в _draw_trees → NameError rw). Правило: якорить
  на уникальную пару «конец блока + заголовок следующего def»; после
  серии правок — py_compile + import + смоук-тест рендера.
- **Рефактор каркаса**: старый блок может остаться → двойной UI и
  конфликт grid-ячеек (двойная навигация 22.08). Правило: grep до/после,
  что старый код исчез; счёт вхождений.
- **Удаление съедает создание переменной**: py_compile ловит только
  синтаксис; NameError вида `no attribute 'content'` всплывает при
  РЕАЛЬНОМ запуске. Правило: после удалений — запуск демо, а не только
  компиляция.

### Диагностика (дополнено 22.08 вечер)
- **Пиксельные пробы по скрину ЧУЖОЙ вкладки дают ложные
  подтверждения**: демо стартует на «Мире», а тёмный сайдбар/панели
  матчатся под пороги штампа/компаса. Правило: сначала убедиться,
  что проверяемый элемент вообще виден (нужная вкладка), потом
  пробовать пиксели.
- **SendKeys/AppActivate ненадёжны** для смены вкладок Tk из чужого
  процесса — фокус уходит мимо. Для автотестов UI лучше PostMessage
  в hwnd или прямые вызовы кода (смоуки).
- **Append-логи обманывают**: трейс от старой версии файла выглядит
  свежим (строки уже не совпадают с кодом). Перед диагностикой усекать
  лог или сверять номер строки трейса с текущим файлом.
- **Заголовки окон с кириллицей**: фильтры MainWindowTitle -match
  работают ненадёжно; надёжно — EnumWindows P/Invoke + PrintWindow
  для скринов фоновых окон. AppActivate подводит при полноэкранных
  приложениях (YouTube).
- **PID-reuse**: ParentProcessId может указывать на мёртвый/переисполь-
  зованный PID. Родство проверять по имени/cmdline родителя.
- **WMI-запуск GUI**: cmd-обёртка владеет процессом, но НЕ окном;
  окно искать у python.exe-ребёнка.

### SQLite WAL и «молчаливые» деградации (урок 25.08, P0-c/P0-d)
- **SQLite в WAL-режиме: copy2 основной базы НЕ равен копии данных** —
  схема/данные живут в -wal до checkpoint. Копирование без
  `PRAGMA wal_checkpoint(TRUNCATE)` даёт пустую/бессхемную базу
  (случай MemorySandbox). Правило: консистентная копия — либо
  wal_checkpoint перед copy2, либо sqlite3 backup API
  (как eddie_data_profile._backup_consistent_db).
- **«if table not in existing: continue» при очистке = молчаливое
  принятие бессхемной базы за норму** — дефект всплывает много позже
  в виде «памяти нет, ошибок нет». Правило: отсутствие ожидаемых таблиц
  в песочнице — это FAIL инициализации, а не skip.
- **try/except pass вокруг записи памяти превращает любую поломку
  хранилища в тихое испарение опыта** (ACTION_CHOICE agent.py:3967–99).
  Правило: глотание допустимо только с журналом падения.
- **Метод поиска «куда уходят события»: шпион на memory.remember +
  счётчик вызовов + список таблиц sqlite_master** быстрее чтения кода:
  leak3_test.py сразу показал «remember calls: 0».

### PowerShell / кодировки
- Кириллица через консоль ломается; python -c с кириллицей падает на
  печати. Временные .py файлы + PYTHONIOENCODING=utf-8 либо \uXXXX-
  паттерны. Не передавать кириллицу аргументами CLI.
- Set-Content/Out-File/Add-Content = BOM/cp1251 яд для исходников.
- После серий правок — байт-проверка: BOM, «?»-литералы, «Ð»-мусор.

## [АКТУАЛЬНО] 23.08: мусор памяти = отравление личности (Эпоха 2)

- Личность, формируемая из событий, наследует ВСЁ что попало в память:
  тестовые эмоции (CONTROLLED_TEST_STATE), битые реплики mojibake-эпохи,
  ассистентские ответы сырой модели. Решение совета: полный чистый лист
  вместо точечных правок; архив обязателен (SHA256-сверка), удаление -
  только после него.
- Отравление контекста историей: RECENT CONVERSATION MEMORY возвращает
  модели её прошлые ответы как образцы; один брак -> снежный ком.
  Лечение: few-shot образцы настоящего голоса в промпте + чистая память.
- Agent() делает MODEL WARM-UP обеих моделей на каждом старте (~60-150 с,
  до 5.5 ГБ): для коротких REPL-сессий это расточительно. Кандидат:
  ленивая загрузка тяжёлой модели по факту роутинга.
- keep_alive у phi4-mini был 15m в трёх местах -> модель висела в RAM
  между диалогами. Теперь 3m (execute/warm-up/fallback).
- Паттерн изоляции данных через env (EDDIE_DATA_DIR) читается константами
  при импорте: переменную ставить ДО первого импорта модулей агента;
  для БД копировать через sqlite backup API, wal/shm не переносить.

## [24.08.2026] Голосовой стек и поведение: уроки дня

- scipy.signal.resample_poly: up<down = СЖАТИЕ сигнала (быстрее+выше),
  up>down = растяжение. Перепутанное направление дало серию «ленивых
  баситых» вариантов и потерянный вечер. Проверять направление первым.
- parselmouth PSOLA рецепты: Multiply frequencies требует 3 аргумента
  (start, end, factor); 'Replace pitch tier' вызывается как
  call([manipulation, tier], 'Replace pitch tier'); Lengthen (PSOLA)
  третий аргумент - ФАКТОР, не абсолютная длительность; медиана питча -
  call(sound.to_pitch(None, floor, ceil), 'Get mean...', 0, 0, 'Hertz').
- Родная команда Praat 'Change gender' на синтетике edge-tts падает с
  'no voiced segments' - использовать ручной PSOLA-конвейер.
- edge_tts.Communicate: rate только со знаком ('+0%' валидно, '0%' нет);
  периодический NoAudioReceived - нужен retry x3 с паузой.
- Отключение warm-up => первый запрос к модели включает её загрузку с диска
  (qwen ~160 c). Фоновый cognition_worker при первом тике сам вызывает phi -
  это выглядит как «EddieAI долго думает», но это холодный старт личности.
- Паттерн «мотивационный вопрос -> контекст-сброс»: вопрос «почему ты это
  выбрал?» обрывает нить и даёт few-shot шаблон («Привет. Рад тебя
  слышать»). Причина: память диалога limit=3 + отсутствие образцов
  рефлексии о мотивации. Лечение: P3 (limit x2) + P1 (few-shot честности).
- «Слова <> дело»: разговорные цели НЕ доходят до GoalManager (goals
  остаются пустыми) - цель существует только как звук. Податливость:
  просьба «ради меня» мгновенно порождает фиктивную цель. Настоящая
  автономия требует умения отказать создателю.
- SambaNova free-тариф: модели видны в /v1/models, но chat = 402 Payment
  Required всегда. Ключ бесполезен без платного плана.
- Доступные из РФ LLM-API (проверено live): Mistral OK, SambaNova OK(402),
  Cloudflare OK; OpenRouter/Groq/Cerebras - 403 гео-блок. HF доступен.

## [24.08] Катастрофа `git checkout --` и восстановление из opencode.db

- **git checkout -- <файл> при горах незакоммиченной работы =
  мгновенная потеря ВСЕГО** (случай: mistral large выполнила
  `git checkout -- core\agent.py` в 13:48, стёрла 47 edit'ов двух
  дней; файл 6020 строк откатился до древних 1037). Правило:
  незакоммиченные драгоценности - сначала бэкап/коммит/стэш, потом
  любые checkout/restore. Особенно опасно доверять checkout модели.
- **opencode хранит ПОЛНУЮ историю tool-вызовов в SQLite**
  (`~\.local\share\opencode\opencode.db`, таблицы part/message/
  session/event): read-выводы содержат ТЕКСТ ФАЙЛА построчно с
  номерами, edit'ы - old/new пары. Это чёрный ящик для восстановления.
- Техника восстановления (проверено): мозаика из read-частей
  («NNN: текст» + хвост «(Showing lines X-Y of Z...)» даёт общий
  размер файла на момент чтения!) + накат completed-edit'ов ASC.
  Покрытие 83% файла из ~220 частей.
- Ограничение: зоны, которые НИКТО не читал и не правил через
  opencode, невосстановимы из БД (у нас 993 строки тел методов).
  Порядок событий в БД ненадёжен: time_created одинаковый у пачки
  частей одного сообщения ассистента.
- Фильтр путей: `fp.endswith("agent.py")` ловит и мои временные
  скрипты вида timeline_agent.py - фильтровать строго по
  `\agent.py` / `/agent.py`.
- shadow-git opencode (`snapshot\<hash>\`) - отдельный git-repo со
  снимками, но коммиты редкие (нашли только 17.08); alternates
  указывает на основной .git - свежих blob'ов там нет.
- bash-дампы кода во временную папку (respond_dump.txt) живут долго -
  проверять %TEMP%\opencode\ на диске, это независимый источник.
